# Фичи iOS, которых нет в Android

iOS-приложение (`~/src/kolco24_ios/kolco24`) — порт этого приложения (stages 0–11), после которого
оно развивалось отдельно. Здесь — что появилось в iOS после порта и ещё не сделано в Android.
Сверено по состоянию на 2026-09-25 (iOS `db905b6`).

Детальные планы каждой фичи — в iOS-репо: `docs/plans/completed/<файл>.md` (указан у каждого пункта).
Это готовые спецификации: контракт сервера, чистая логика, тест-кейсы.

## Фичи

### 1. Способ проверки КП (`check_method`: offline / cloud / local)

План: `20260924-check-method.md`. iOS: `Core/Marks/CheckMethod`, `ScanModel`, `ScanSheet`,
`MarkUploadRepository.confirm`, `MarksView`, `PhotoLightboxView`.

- Android хранит `TagEntity.checkMethod`, но показывает его только в админской проверке чипа; на счёт не влияет.
- Правило: `offline` — как сейчас. `cloud` / `local` — взятие засчитывается, только если облачный / LAN-сервер
  принял отметку **пока открыт экран скана**. Фоновая выгрузка отметку отправляет, но не подтверждает.
- Схема: `marks.checkMethod` + `marks.confirmedAt` (wall ms, `NULL` = не подтверждено). `confirmedAt` ставит
  только confirm из экрана скана; `addMember`/upsert его не сбрасывают.
- «Взято»/очки считаются через `isCounted` = `complete && (offline || confirmedAt != null)`, а не голый `complete`.
- Экран скана: когда состав полный, для cloud/local — режим подтверждения: POST одной отметки
  (в обход `tryLock` дренажа), ретраи каждые 3 с, таймаут 20 с; статусы «отправка / подтверждено / ошибка».
  Фанфары и «Готово!» — только после подтверждения.
- Вкладка «Отметки»: неподтверждённые взятия видны (приглушённая плитка + иконка), но не считаются;
  отдельная карточка-уведомление; статус в лайтбоксе.
- Фото-отметки всегда `offline`. Неизвестное значение → `offline`. Сервер переименовывает значения
  (`online` → `cloud`, `local_server` → `local`); до этого старые значения парсятся как `offline`.

### 2. Запись кодов на браслеты участников (админка)

План: `20260923-member-chip-provisioning.md`. iOS: `MemberProvisioningView`, `App/MemberProvisioningModel`,
`Core/Admin/MemberProvisioningLogic`, `Net/Dto/MemberTagBind`.

- Новый экран «Записать браслет участника» в секции «Чипы» админки. На браслет пишется серверный секретный
  код в формате `K24` с типом `CHIP_TYPE_PARTICIPANT = 0x2` (в Android константа объявлена, но не используется).
- Два тапа, как у КП: тап 1 — UID → запрос кода; тап 2 — тот же UID → запись (header last) + read-back.
- UID есть в локальном пуле `member_tags` → номер известен. UID не в пуле или сервер ответил `404` →
  админ вводит номер (с автоинкрементом).
- Эндпоинт: `POST /app/race/<id>/member_tags/bind/` (подпись `X-App-*` + админский Bearer).
  `201`/`200` — успех с `code`; `404` — нужен номер; `409` — «Браслет уже привязан к другому участнику».
- Чтение чипа должно понимать тип: `parseChipRecord` сейчас только для КП.
- «Проверить чип участника» дополнительно показывает, записан ли на браслет код участника
  (в Android сейчас отличает только «браслет из пула» от «чипа КП»).

## Мелкие UI-доработки плиток «Отметок»

Из `2717e86 fix: photo tile square`. Дизайн Android другой (плитка залита цветом КП), так что это не
обязательно к переносу — список для сверки:

- Большой моно-токен номера КП по центру на NFC- и фото-плитках; фото затемнено, чтобы белый номер читался.
- Цвет КП — треугольник в верхнем левом углу плитки (вместо заливки).
- Подпись метрик: единицы в подписях («Взято КП» / «Баллов»), в значениях только числа.

## Не требует переноса

iOS-специфичные исправления, у Android этих проблем нет:

- Остановка системного NFC-листа перед закрытием, кнопка «Сканировать» для перезапуска в провижининге
  (CoreNFC-лист модальный; в Android — reader mode).
- Приглушение чужого аудио только на время звука скана (`AVAudioSession`).
- Конфетти при завершении взятия — в Android уже есть (`ScanScreen.ConfettiOverlay`).
- Полоса «NFC недоступен» вместо постоянной «NFC активен» — в Android уже есть `NfcState.Disabled`.
