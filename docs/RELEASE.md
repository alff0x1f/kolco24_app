# Публикация в Google Play

Пошаговая инструкция для `org.kolco24.app`. Аккаунт разработчика личный, создан до ноября 2023 —
закрытое тестирование (12 тестировщиков / 14 дней) не требуется, можно сразу в «Рабочую версию».
Названия пунктов меню — как в русском интерфейсе Play Console.

## 1. Однократная настройка подписи

Ключ загрузки (upload key): `/Users/alff0x1f/src/kolco24_app_key/key_kolco24app` — тот же, которым
подписывалось старое `ru.kolco24.kolco24` в открытом тестировании.

1. Узнать alias:
   ```
   keytool -list -keystore /Users/alff0x1f/src/kolco24_app_key/key_kolco24app
   ```
2. Добавить в `local.properties` (файл не коммитится):
   ```
   kolco24.signing.storeFile=/Users/alff0x1f/src/kolco24_app_key/key_kolco24app
   kolco24.signing.storePassword=...
   kolco24.signing.keyAlias=...
   kolco24.signing.keyPassword=...
   ```
   Для CI — те же значения в env `KOLCO24_SIGNING_STORE_FILE` / `_STORE_PASSWORD` / `_KEY_ALIAS` /
   `_KEY_PASSWORD`. Без них release собирается **неподписанным** (debug-сборки и проверки не
   затрагиваются).
3. Положить keystore и все пароли в менеджер паролей. Ключ в репозиторий не попадает.

## 2. Сборка релиза (каждый раз)

1. **Версия** — в `app/build.gradle.kts` увеличить `versionCode` (обязательно, Play не примет тот же
   или меньший) и `versionName`.
2. **Проверки**:
   ```
   ./gradlew lintDebug testDebugUnitTest
   ```
   Если с прошлого релиза менялась схема Room — ещё `./gradlew connectedDebugAndroidTest`.
3. **Smoke-тест release на телефоне**:
   ```
   adb uninstall org.kolco24.app   # debug подписан другим ключом; локальные данные удалятся
   ./gradlew assembleRelease
   adb install app/build/outputs/apk/release/kolco24_v<versionName>-release.apk
   ```
   Проверить руками: NFC-отметку, фото-отметку, запись трека (уведомление сервиса), карту,
   синхронизацию.
4. **Bundle для Play**:
   ```
   ./gradlew bundleRelease
   ```
   Результат: `app/build/outputs/bundle/release/kolco24_v<versionName>-release.aab`.
5. **Проверить подпись**:
   ```
   jarsigner -verify -verbose:summary app/build/outputs/bundle/release/*.aab
   ```
   Должно быть `jar verified`. `jar is unsigned` — `local.properties` не прочитан.
6. **Тег**: `git tag v<versionName> && git push --tags`.

Минификация (R8) выключена намеренно. Предупреждение Play про отсутствие deobfuscation file можно
игнорировать.

## 3. Карточка в Play Console (однократно)

### 3.1 Создать приложение

Все приложения → **Создать приложение**: название «Кольцо 24», язык по умолчанию — русский,
«Приложение», «Бесплатное», принять декларации.

### 3.2 Политика конфиденциальности

Опубликована: https://kolco24.ru/page/privacy_app/ (общая для iOS и Android). При изменении
собираемых данных обновить её и Data safety (3.3). Что в ней должно быть:

- кто оператор данных и контакт для связи;
- какие данные собираются: GPS-трек во время записи, координата отметки КП, фото отметок, данные
  команды и участников, идентификатор установки;
- зачем: учёт прохождения и результатов соревнования;
- куда передаются: только на сервер kolco24 (и LAN-сервер на соревновании), третьим лицам — нет;
- сколько хранятся и как запросить удаление.

### 3.3 Контент приложения

Меню слева: **Политика → Контент приложения**. Без всех пунктов выпуск не отправить.

- **Политика конфиденциальности** — URL из 3.2.
- **Доступ к приложению** — проверяющему нужна гонка/команда. Описать, как попасть в основные
  функции (какую гонку и команду выбрать, тестовые NFC-метки не нужны — есть фото-отметка), либо
  дать тестовую гонку. Иначе возможен отказ «не удалось проверить функции».
- **Реклама** — нет.
- **Возрастные ограничения** — анкета IARC, насилия/азартных игр нет.
- **Целевая аудитория** — 18+ (или 13+). Не выбирать возраст младше 13 — иначе применяется политика
  Families.
- **Безопасность данных** (Data safety):
  - Местоположение → точное: собирается, обязательно при записи трека, для функций приложения.
  - Фото и видео → фото: собираются (кадры фото-отметок).
  - Личная информация → адрес электронной почты: собирается, необязательно (вход организатора/судьи).
  - Идентификаторы устройства → идентификатор установки (случайный, не рекламный).
  - Третьим лицам не передаются; рекламы и сторонней аналитики нет.
  - Шифрование при передаче — **нет**: облако по HTTPS, но LAN-сервер на соревновании по HTTP, а
    вопрос про *все* данные.
  - Удаление данных — по запросу (контакт из политики).
- **Разрешения для сервисов переднего плана** — `FOREGROUND_SERVICE_LOCATION`, задача
  «Навигация / отслеживание пути пользователя». Нужна ссылка на видео (YouTube, «доступ по ссылке»,
  30–60 с): старт записи трека → уведомление в шторке → остановка.
- Финансовые функции, здоровье, госприложение, новости — «нет».

### 3.4 Основная страница в магазине

**Развитие → Страница в Google Play → Основная страница**:

- название (до 30 символов), краткое описание (до 80), полное описание (до 4000);
- значок 512×512 PNG, графический баннер 1024×500;
- минимум 2 скриншота телефона.

**Настройки магазина**: категория «Спорт», email для связи, сайт.

### 3.5 Страны

**Рабочая версия → Страны/регионы** — Россия и остальные по желанию.

## 4. Выпуск

### 4.1 Первый выпуск

1. **Тестирование и выпуск → Рабочая версия → Создать выпуск**.
2. **Подписание приложений Google Play**: оставить по умолчанию — ключ подписи генерирует Google.
   `key_kolco24app` становится ключом загрузки. Если он потерян — **Целостность приложения → Подпись
   приложения → Запросить сброс ключа загрузки**; приложение не теряется.
3. Загрузить `.aab`, написать примечания к выпуску (ru-RU).
4. **Проверить выпуск** → исправить ошибки → **Отправить на проверку**.
5. Первая проверка нового приложения — от нескольких дней до 1–2 недель. Отправлять заранее, не
   накануне гонки.
6. По желанию: **Обзор публикации → Управляемая публикация** — после одобрения приложение ждёт
   кнопки «Опубликовать», а не выходит само.

### 4.2 Старое приложение `ru.kolco24.kolco24`

После выхода нового: в старом приложении **Настройки → Расширенные настройки → Отменить публикацию**.
Тестировщикам открытого теста заранее дать ссылку на новое. Данные со старого приложения не
переносятся.

### 4.3 Следующие релизы

1. Раздел 2 (с увеличенным `versionCode`).
2. **Рабочая версия → Создать выпуск** → загрузить `.aab` → примечания → отправить на проверку.
3. Для рискованных релизов — поэтапное развёртывание (например, 20%), затем увеличить до 100%.
