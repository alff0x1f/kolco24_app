# Data layer — per-file design notes

Per-file notes for `data/**`, `Kolco24App.kt`/`AppContainer.kt`, and `TrackRecordingService.kt`: the "why" behind each file, its gotchas, and test coverage. Read the relevant bullet before modifying a file here; update it when behavior changes. Cross-cutting rules live in `/CLAUDE.md` («Conventions & gotchas») and are assumed, not repeated.

## Data layer

- `Kolco24App.kt` — `Application`; builds `AppContainer`. **Launch A** (`onCreate`): `refreshRaces()` then prefetch the nearest race (`nearestRaceId`) — teams+legend+member-tags concurrently via `syncCoordinator.sourceFor(nearest)` (pin-aware: re-entering local mode after a process restart prefetches from LAN); also fires a best-effort `sweepOrphanPhotoDirs()` on startup (deletes `filesDir/marks/<id>/` directories whose markId has no live `MarkEntity` row — reclaims frames from killed mid-capture sessions). (The `*.mbtiles.part` sweep is **not** here — it runs inside `MapRepository`'s startup job so no download can start before it; see below.) **Launch B**: `collectLatest` the selected team; inside a `supervisorScope` (a team switch cancels in-flight fetches), when `sourceFor(raceId) == Local` first `probeLocalAndRenew(raceId)` (heartbeat + immediate handback detection), then refresh legend/teams/member-tags via `sourceFor(raceId)` **re-read** after the probe (it may have just unpinned), and fire `trackRepository.uploadAllPending()` + `markRepository.uploadAllPending()` + `judgeScanRepository.uploadAllPending()` so stranded points/takes/piks opportunistically re-send. All on `applicationScope`.
- `AppContainer.kt` — manual DI (no Hilt). Builds the OkHttp client (`AppSignatureInterceptor` outer + `ServerTimeInterceptor` inner), `ApiClient` (cloud) + `localApiClient` (LAN, 3 s timeouts, **no** `ServerTimeInterceptor`), Room `AppDatabase`, all repositories, the preference stores, and `applicationScope`. **Construction-order cycles** (interceptor wants the bearer token / trusted time; repos want `ApiClient`) are broken by passing **lambdas** read only at request time (`tokenProvider = { adminAuthRepository.token() }`, `nowSeconds = { trustedClock.signingSeconds() }`). `cachedBootCount` is read **once per process** (`Settings.Global.BOOT_COUNT`). **Trusted-time wiring:** `ServerTimeInterceptor.onServerTime` bridges to `trustedClock.onTimeCandidate`; `lanTimeVerifier` + `syncLanTime()` (fresh nonce → `localApiClient.fetchLanTime` → verify → `onTimeCandidate`, RTT measured tightly around the call since the LAN client has no `ServerTimeInterceptor`) is threaded into `SyncCoordinator` as its `syncLanTime` seam; `anchorTrustedTimeFromGps(fix)` snapshots wall+boot and offers a `gpsTimeCandidate`, called from the track-service fix path and from a **decorator wrapping `currentLocationProvider`** that re-anchors on every fresh one-shot fix; `trustedAt = trustedClock::trustedAt` is passed to both `MarkRepository` and `JudgeScanRepository` for upload backfill. Public flows `trackRecordingState`, `trackUploadOutcomes`, `markUploadOutcomes`, `judgeScanUploadOutcomes` (the last three are **transient in-memory** per-target outcome maps — no Room table, no migration; self-heal after a restart; `judgeScanUploadOutcomes` is keyed by `Pair<Int, UploadTarget>` (raceId, target), distinct from the `(TrackScope, UploadTarget)` keys of the other two). Owns the eager `scanFeedback: ScanFeedbackPlayer` (constructed in `onCreate` so its async `SoundPool.load()` is warm before the first tap), threaded down to the scan/bind/check/provision/judge-scan overlays and the idle path. `clearDatabase()` (debug/test only) wipes all tables incl. ETags **and** deletes `filesDir/marks/` so photo frames never outlive a DB wipe — it does **not** touch downloaded race maps (a map file is not DB state). **Race map:** `mapFileStorage` (`noBackupFilesDir/maps/`) and `mapRepository` (**`by lazy`** only to skip building its OkHttp client in UI-less processes — in practice `Kolco24AppRoot`'s `val mapRepo = container.mapRepository` constructs it on first composition; construction does **no** disk I/O: the `.part` sweep + `downloaded` seed run on `applicationScope`) built over a **separate plain `OkHttpClient`** (15 s connect / 60 s read for a multi-MB body; **no** `AppSignatureInterceptor`/`ServerTimeInterceptor` — `map_url` is an unsigned static file, possibly on another host, and must never anchor trusted time), `MapDownloader(validate = ::validateMbtiles, usableSpace = { mapFileStorage.ensureRoot().usableSpace })`, `scope = applicationScope` (a download outlives the Map tab), `readMetadata = ::readMbtilesMetadata`. **Local-mode-switch state:** `raceLeaseStore: RaceLeaseStore` (prefs-backed) seeds `raceLease: MutableStateFlow<RaceLease?>` synchronously at construction (a `StateFlow`, not a plain field, so the Settings switch collects live handback/expiry); `nowMs: () -> Long` prefers `trustedClock.trusted()` over wall clock; `isRacePinned: (raceId) -> Boolean` wraps `isPinned(raceLease.value, raceId, nowMs())` and is threaded into `TeamRepository`/`LegendRepository`/`MemberTagsRepository` (not `RaceRepository` — races are global, not race-scoped); `syncCoordinator: SyncCoordinator` binds all of the above plus the four repos' refresh calls as lambda seams (`fetchSync` collapses any `localApiClient.fetchSync` non-`Success` result to `null`). `judgeScanRepository: JudgeScanRepository` wires `cloudUploader = apiClient::uploadJudgeScans`, `localUploader = localApiClient::uploadJudgeScans`, `dao = database.judgeScanDao()`, `installId`, `onUploadOutcome = { raceId, target, kind -> judgeScanUploadOutcomes.update { it + ((raceId to target) to TargetUploadOutcome(kind, System.currentTimeMillis())) } }` — same lazy-by-lambda shape as the other uploaders.
- `data/api/AppSignatureInterceptor.kt` — HMAC-SHA256 signs every request (canonical string per `docs/API.md`, 6 headers); `ts`/signature recomputed per call. Body hash by buffering the built request; a null/one-shot/unbufferable body falls back to `EMPTY_BODY_SHA256` (signing never crashes). `tokenProvider` adds the admin bearer; `nowSeconds` is the trusted-time `ts` source. **Self-heal retry-once (GET/HEAD only):** a `403` with a changed `ts` re-signs and retries once (the inner interceptor already re-anchored from the `403`'s `Date`) — **POST is never auto-retried** (a `403` is indistinguishable from a real auth failure; replay ≠ idempotent). Tested by `SigningTest`.
- `data/api/ApiClient.kt` — `FetchResult` (GET: `Success`/`NotModified`/`Forbidden`/`Error`) via one `conditionalGet(...)` with `If-None-Match`; `PostResult` (`Success`/`BadRequest`/`Unauthorized`/`Forbidden`/`Conflict`/`RateLimited`/`Offline`/`Error`) via one `post(...)` where **`parse` runs only on the 200/201 branch**. Methods: `fetchRaces`/`fetchTeams`/`fetchLegend`/`fetchMemberTags`; `login`/`logout`/`bindTag`/`uploadTrack`/`uploadMarks`/`uploadMarkPhoto`/`uploadJudgeScans`; `fetchLanTime(nonce)` (LAN client, signed time endpoint) returns the raw `200` body (`LanTimeResponse` = `LanTimeDto` + `X-App-Signature` header) — non-`200`/`404` (endpoint not deployed)/garbled/offline → `null`, the pure `LanTimeVerifier` does the nonce-echo + HMAC. `uploadMarks`/`uploadJudgeScans` carry `source_install_id` in the **body** (unlike track). `post()` takes an optional `mediaType` (default `JSON_MEDIA_TYPE`); `uploadMarkPhoto(raceId, markId, frameId, bytes)` posts to `mark/<markId>/photo/<frameId>` with `IMAGE_JPEG_MEDIA_TYPE` and a `{ Unit }` parser (empty `200` body) — `frameId` is the frame's `<uuid>` filename stem, doubling as the server-side idempotency key; `404` (endpoint not deployed / mark row not landed) maps to `PostResult.Error` and self-heals on the next drain trigger. `uploadJudgeScans(raceId, sourceInstallId, scans)` posts to `judge_scans/` (no `team_id` — see `docs/design/UPLOAD.md`; server not yet implemented, so both targets return non-`Success` until it ships). The same `uploadTrack`/`uploadMarks`/`uploadMarkPhoto`/`uploadJudgeScans` serve both cloud and LAN — the target is the choice of `ApiClient` **instance**. `defaultOkHttpClient(...)` installs signature outer, optional `ServerTimeInterceptor` inner, no response `Cache` (every `Date` is live). Tested by `ApiClientTest`/`ApiClientMarksTest`/`TrackUploadTest`.
- `data/api/ServerTimeInterceptor.kt` — re-anchors `TrustedClock` from the HTTP `Date` header on every **network** response (free, backend-free server time). Pins the parsed epoch to an overflow-safe RTT-corrected midpoint **with `uncertaintyMs = rtt/2 + DATE_HEADER_GRANULARITY_MS` (500 — the `Date` header's second granularity)**, offered as a `TimeCandidate` to `TrustedClock.onTimeCandidate`; gated to network-only, RTT in `0..maxRttMs`, parseable `Date`. Trust is structural (installed only on the single `/app/` host). **Tested** (`ServerTimeInterceptorTest`) — a trust boundary, so the untested-adapters convention is waived.
- `data/api/dto/` — `@Serializable` snake_case DTOs, `ignoreUnknownKeys = true`. `RacesResponse`/`TeamsResponse` (note `start_number` is nullable/defaulted — undocumented; `RaceDto.mapUrl` = `map_url`, nullable, default `null` — absent/`null` means the race has no offline map, mapped straight to `RaceEntity.mapUrl` by `RaceRepository`'s `toEntity`); `LegendResponse` (legend always returned; a **locked** `CheckpointDto` carries an `enc:{iv,ct}` envelope **instead of** plaintext cost/description, so both nullable and `enc != null` is the locked sentinel; `color` is public, in both branches; `tags[].checkpoint_id` is the stable id; `totalCost`/`scoringCount` are top-level race aggregates — `scoringCount` is the count of CPs with `cost > 0` incl. locked, the denominator for the taken-КП counter, `default 0` for forward-compat before the server ships the field); `MemberTagsResponse` (chip pool, `nfc_uid` already normalized server-side); `AuthDtos`/`TagDtos` (admin login + `TagBindResponse.code` = the hex written onto the chip); `TrackDtos`/`MarkDtos`/`JudgeScanDtos` (upload contracts in `docs/design/UPLOAD.md`); `LanTimeDtos.kt` (`LanTimeDto` = `server_ms`/`nonce`, the signed LAN time endpoint body — ms-granular, verified by `LanTimeVerifier`); `SyncDtos.kt` (`SyncManifestDto` — `race`/`data_source`/`lease_ttl_seconds`/`lease_expires_at`, fetched via `ApiClient.fetchSync(raceId)`, no ETag/304 by design; `versions` deliberately unmapped — see the lease bullet below). **Mark field names differ from `MarkEntity`** (`cp_nfc_uid ← cpUid`, `wall_ms ← takenAt`, `trusted_ms ← trustedTakenAt`, `elapsed_at ← elapsedRealtimeAt`); the pure `MarkEntity.toDto()` merges `present` with `presentDetails`, emitting a documented sentinel (`nfc_uid=null, number=0`) for a scored member with no snapshot so none is lost. `JudgeScanEntity.toDto()` mirrors the same field-rename shape (`wall_ms ← takenAt`, `trusted_ms ← trustedTakenAt`, `elapsed_at ← elapsedRealtimeAt`) but is a flat 1:1 copy — no `present`/snapshot merge, since a judge pik has no roster dimension. Tested by `MarkDtoMappingTest`/`TrackUploadTest`/`JudgeScanDtoTest`.
- `data/db/` — Room **v6** (`exportSchema = true`, schemas committed). `MIGRATION_1_2` adds `marks.presentDetails` + `index_marks_raceId`; `MIGRATION_2_3` (Phase 2, photo-mark upload) adds `marks.photosUploadedLocal`/`photosUploadedCloud` (`INTEGER NOT NULL DEFAULT 0`, per-target frame-drain flags); `MIGRATION_3_4` adds `legend_meta.scoringCount` (`INTEGER NOT NULL DEFAULT 0`, additive, no backfill — repopulates on the next legend refresh); `MIGRATION_4_5` (judge start/finish scan) creates `judge_scans` (nullable `bootCount`/`trustedTakenAt`, `NOT NULL` everything else) + `index_judge_scans_raceId` — column types/nullability and the index name must match Room's generated schema exactly, or `runMigrationsAndValidate` fails against `5.json`; `MIGRATION_5_6` (map tab) adds nullable `races.mapUrl TEXT` **and** `DELETE FROM sync_meta WHERE resource = 'races'` — drops the races ETag of **every** origin (cloud + LAN), since a pre-v6 client may hold the ETag of a body that already carried `map_url` but persisted rows without it, and a `304` on that ETag would pin `mapUrl = NULL` forever; other resources' ETags are untouched; append future migrations with their own schema json (see the Room convention above). `MigrationTest` (instrumented) guards all five (`migrate5To6`: race row survives with `mapUrl` NULL, both origins' races ETags dropped, teams ETag intact). Tables: `RaceEntity` (also the domain model — no third layer; nullable `mapUrl` since v6), `SyncMetaEntity` (per-origin/resource ETag), `CategoryEntity` (`order` → `sortOrder`, reserved word), `TeamEntity` (`members` as a JSON column), `SelectedTeamEntity` (single row; `observe()` emits `null` = "no team chosen"), `CheckpointEntity` (cost/description **nullable** for locked CPs + `locked`/`encIv`/`encCt`/`color`; does **not** track `taken` — that's team-scoped, derived from marks), `LegendMetaEntity` (per-race legend aggregates the server computes and the client can't derive offline while locked: `totalCost` and `scoringCount`, the count of CPs with `cost > 0` incl. locked — see `LegendRepository`), `TagEntity` (PK `(raceId, bid)`), `MemberTagEntity` (per-race chip pool, PK `(raceId, nfcUid)`), `MemberChipBindingEntity` (**local-only** member↔chip, PK `(teamId, numberInTeam)`), `MarkEntity` (**local-only** take log, PK = client UUID — snapshots КП meta, `present`/`presentDetails`, `complete`, the five `TimeSample` time columns, the nullable `loc*` anti-cheat GPS columns, and the Phase-2 `photosUploadedLocal`/`photosUploadedCloud` flags), `TrackPointEntity` (**local-only** GPS log, PK = client UUID — `segmentId` per recording session, monotonic `elapsedRealtimeAt` + `bootCount`, back-projected `wallMs`, `trustedMs`), `JudgeScanEntity` (**local-only, write-once** judge start/finish pik, PK = client UUID, scoped by `raceId` **only** — no team dimension, since one judge station covers every team; `Index("raceId")` only, no unique constraint — repeat piks of the same participant are expected and each gets its own row). **DAO gotchas:** `CheckpointDao.replaceAllForRace` is **preserve-on-resync** (re-applies prior plaintext to a still-locked incoming id so a `200` never re-locks an offline-unlocked CP); `MarkDao.attachLocation` is a **column-scoped UPDATE** (not a full-row read-modify-write — it runs fire-and-forget in parallel with `addMember`, so a full write would lost-update) and **resets `uploaded*` to 0** to re-queue a row whose GPS fix landed after its first upload (server upserts by id → idempotent); `MarkDao.attachPhotos` (`updatePhotoPath`) is also a **column-scoped `@Transaction`** (only `photoPath`, `updatedAt`, and — Phase 2 — `photosUploadedLocal`/`photosUploadedCloud` change; `uploaded*` is **not** reset — `photoPath` is not in the marks DTO) and **resets `photosUploaded*` to 0** so appending frames re-queues the frame drain. **Phase 2 (photo upload):** the `method != 'photo'` filter is **dropped** from `unuploadedLocal`/`unuploadedCloud`/`pendingUploadScopes` — photo rows (empty `cpUid`/`cpCode`/`present`) now flow through the shared `/marks/` batch (server must partial-accept, see `docs/design/UPLOAD.md`); `uploadCounts` is truthful per target only when metadata **and** frames are done (`uploadedX AND (photoPath IS NULL OR photosUploadedX)`); `pendingUploadScopes` is widened to also return scopes with pending frames; `framePendingLocal`/`framePendingCloud(raceId, teamId, limit)` are the **method-agnostic** frame-drain candidate queries (`uploadedX=1 AND photosUploadedX=0 AND photoPath IS NOT NULL`, so an NFC take with attached photos drains identically to a standalone photo mark); `setPhotosUploadedLocalIfUnchanged`/`setPhotosUploadedCloudIfUnchanged(id, updatedAt)` are **version-guarded** flips (mirror `markUploadedCloudIfUnchanged`) so an `attachPhotos` racing mid-drain can't be clobbered back to `1` with a new frame unsent; `allIds()` backs the startup orphan sweep. **Upload-status page additions:** `uploadCountsMetadata(teamId, raceId): Flow<UploadCounts>` mirrors `uploadCounts` but drops the `photoPath`/`photosUploadedX` term (bare `uploadedLocal`/`uploadedCloud`) — answers "did the take row reach the server?" independent of its photos; `photoFrameRows(teamId, raceId): Flow<List<PhotoFrameRow>>` returns `(photoPath, photosUploadedLocal, photosUploadedCloud)` for in-scope rows where `photoPath IS NOT NULL`, folded by pure `MarkRepository.foldPhotoFrameCounts` into a frame-granular `UploadCounts`. Ordering is reboot-safe (`COALESCE(trustedMs, wallMs)`, then boot, then monotonic, then id). The JSON converters' round-trips are tested; `CheckpointDaoTest` (instrumented) guards preserve-on-resync; `MarkDaoTest` (instrumented) guards the frame-drain queries, `setPhotosUploaded*IfUnchanged`, `attachPhotos` column-scope/reset, and `uploadCountsMetadata`/`photoFrameRows`; `JudgeScanDaoTest` (instrumented) guards `unuploadedLocal`/`unuploadedCloud` scoping + ordering, `markUploadedLocal`/`markUploadedCloud`, `pendingUploadRaces`, and `uploadCounts` (raceId-scoped aggregate, mirrors `MarkDao.uploadCountsMetadata` with the teamId term dropped — no schema change, existing `judge_scans` columns only).
- `data/lease/RaceLease.kt` + `RaceLeaseStore.kt` / `data/SyncSource.kt` / `data/sync/SyncCoordinator.kt` — the **local-mode-switch** lease/pin subsystem (race-day LAN pin; supersedes the abandoned lease-handoff plan, see memory `local-refresh-lease-plan`). `RaceLease(raceId, expiresAtMs)` pure model: `renewedLease` precedence `serverTtlSec` (clock-skew-immune) → `serverLeaseExpiresAtSec` (absolute, relies on a sane server clock) → `nowMs + DEFAULT_LEASE_MS` (12 h client default while the backend's lease is stubbed `null`); `isPinned(lease, raceId, nowMs)`; `applySyncResponse(manifest, raceId, nowMs): LeaseAction` (`Renew`/`Clear`/`Keep` — **never renews** on a `null` manifest, a manifest for a different race, or an unrecognized `data_source`). `RaceLeaseStore` copies the `ClockAnchorStore` shape: one delimited prefs key (`"$raceId|$expiresAtMs"`, atomic), malformed input → `null`. `SyncSource { Cloud, Local }` is the routing enum threaded through the four sync repos (default `Cloud`). `SyncCoordinator` is thin orchestration over lambda seams (the project's `tokenProvider` idiom — `SyncCoordinatorTest` injects fakes, no MockWebServer/DAO setup): `sourceFor(raceId)` (`Local` iff pinned); `probeLocalAndRenew(raceId)` (one LAN `fetchSync` → `applySyncResponse` → executes the `LeaseAction` — the single heartbeat/handback-detection primitive used at all three probe points: switch-on, pinned Launch B, pinned pull-to-refresh; **no periodic timer**; it also fires `syncLanTime` (a `suspend () -> Unit` seam, default no-op) **outside** the lease lock and **FIRST — before** the freshness-checked `/sync/` manifest fetch — re-anchoring trusted time from the signed `/app/time/` endpoint (time, not lease state). `syncLanTime` is fired **unconditionally**, *not* gated on a reachable manifest, in both `probeLocalAndRenew` **and** `enterLocalMode`: request `X-App-Ts` is stamped from trusted time (`signingSeconds()`), so a skewed `NoSync` clock `403`s every freshness-checked signed request (the `/sync/` manifest included) against the ±300 s window, while `/app/time/` is exempt (server contract in `UPLOAD.md`). Anchoring *before* the manifest lets it be re-signed with corrected trusted time and pin/renew on the **first** attempt; probing after would leave the first switch-on `403`ing → `null` manifest → `LocalUnreachable`/`Keep`, anchoring only in time for a later retry. A genuinely-down LAN is just a cheap fast-fail no-op, so the manifest still fails and the flow yields the same outcome as before. **raceId-ownership guard (renew/clear):** because `syncLanTime` suspends *before* `leaseMutex` is taken, the mutex's FIFO fairness no longer enqueues an in-flight probe ahead of a later-fired switch-off (or a fresh switch-on for another race), so a probe can resume to find the lease cleared or **replaced**. `probeLocalAndRenew` therefore decides on the **current** lease (re-read under the lock — *not* a pre-probe snapshot): `Renew` (`local`) writes only if **this** `raceId` is still an active pin (`isPinned(currentLease, raceId, now)`) — a `null` lease must not re-pin from unpinned, another race's pin must not be touched; `Clear` (`cloud` handback) releases only if `currentLease?.raceId == raceId` — even after a concurrent **same-race** renew moved the expiry, a real handback still lands; any other case is `Keep`. This single rule satisfies every prior case at once: a stale cross-race `cloud` probe leaves race B's newer pin alone (raceId mismatch → Keep); a probe resuming after `exitLocalMode()` cleared the lease neither re-pins nor clears (`null` → Keep); a mid-probe same-race renew no longer strands a later `cloud` handback (raceId match → Clear) — the failure of the earlier snapshot **value-equality** guard, which returned Keep whenever `readLease() != snapshot`. No generation field is needed — the lease is idempotent state. (`Keep` stays a no-op; `enterLocalMode`/`exitLocalMode` can't race each other thanks to `localModeBusy`.) Guarded by `SyncCoordinatorTest.probe_doesNotClearNewerPin_whenStaleCrossRaceProbeReturnsCloud` + `probe_doesNotPin_whenLeaseIsNull` + `probe_clearsLease_onSameRaceCloudHandback_evenAfterConcurrentRenewChangedExpiry` (plus `probe_doesNotRepin_whenLeaseClearedDuringTimeProbe`). `enterLocalMode()`/`exitLocalMode(): LocalModeOutcome` (switch on/off — on: LAN reachable + `local` → pin + LAN fan-out; reachable + `cloud`/unrecognized → no pin + **Cloud** fan-out (a server disclaiming authority must not have its rows persisted); unreachable → nothing written, lease untouched; off: unconditional unpin + Cloud fan-out); `refreshAll(raceId)` (the PTR body — pinned → probe first, then fan-out via `sourceFor` **re-read** post-probe); `combineRefreshResults` folds a fan-out by explicit severity (`HttpError > Forbidden > Offline > Updated > NotModified > Skipped`). **Connectivity loss never releases the pin** — only expiry, server handback, or the switch does.
- `data/RaceRepository.kt` / `TeamRepository.kt` / `LegendRepository.kt` / `MemberTagsRepository.kt` — per-resource sync repos following the **repo refresh pattern** (above); each stores its ETag in `sync_meta` under a resource key. `LegendRepository` also persists tags and owns `unlock(raceId, code): UnlockOutcome` — the **offline reveal path**: `bid` → tag lookup → `LegendCrypto.unlock(...)` on `Dispatchers.Default` → `Revealed` persists each CP via `checkpointDao.reveal(...)`. `refreshLegend` upserts `LegendMetaEntity(raceId, response.totalCost, response.scoringCount)`; `totalCostForRace`/`scoringCountForRace(raceId): Flow<Int>` map `legendMetaDao.observeForRace(raceId)` to each aggregate (`?: 0`, so a cold cache or a pre-rollout server response reads as `0`). `TeamRepository` owns the selected team (`selectTeam`/`clearSelectedTeam`). `MemberTagsRepository` adds `hasBeenSynced(raceId)` (writes a synced-marker when the pool is served without an ETag) so the bind sheet distinguishes "not fetched" from "genuinely empty"; `observeHasBeenSynced(raceId)` is the Flow-backed twin (`SyncMetaDao.observeEtagsExist`, re-emits on every `sync_meta` write) for hosts like `JudgeScanScreen` that must not get stuck on a stale `false` read while a fetch is still in flight. **`SyncSource` routing:** `TeamRepository`/`LegendRepository`/`MemberTagsRepository`'s refresh methods take a `source: SyncSource = SyncSource.Cloud` param and an injected `isRacePinned` lambda — a `Cloud` call for a currently-pinned race returns `RefreshResult.Skipped` **both** at entry (before the network call) **and** re-checked in the `200` branch (an in-flight cloud response must not clobber fresher local rows just-pinned mid-flight); `RaceRepository.refreshRaces` takes the same `source` param but has **no** pin guard (races are a global list, not race-scoped) — it's only ever called with an explicit `Local` from inside `SyncCoordinator`. `RefreshResult` gained a `Skipped` case (`refreshErrorMessage` in `ui/common/PullToRefresh.kt` treats it as silent, same as `Updated`/`NotModified`). Tested by `MemberTagsRepositoryTest`.
- `data/MemberChipBindingRepository.kt` — **local-only** member↔chip bindings (never uploaded). The warn+allow reassign is an atomic `@Transaction reassign` in the DAO (a chip is never momentarily on two slots); the decision stays in `decideBind`. **Binding-key assumption:** keyed by `(teamId, numberInTeam)` because a member exposes no stable participant id — relies on `number_in_team` being stable across `refreshTeams`; if the backend ever reorders slots a binding could re-associate (no mismatch detection). Tested by `MemberChipBindingRepositoryTest`.
- `data/MarkRepository.kt` — **local-only** take events with the dual-target upload loop (above). A take is **two-phase**: `startKpTake(...)` the moment the КП chip is scanned (fresh UUID, snapshots meta + roster size + buffered members + the five `TimeSample` times, upserts so it survives process death); `addMember(...)` adds each scanned member to `present` + `presentDetails` (set-semantics). `attachLocation(markId, fix)` is the fire-and-forget third phase (anti-cheat coordinate; `null` fix = no-op). **Photo-mark additions:** `createPhotoMark(markId, cp, raceId, teamId, paths, expectedCount, sample)` — standalone photo take: `method="photo"`, `complete=true`, `present=[]`, `cpUid=""`; `markId` is minted by the entry point **before** the camera opens so frames write under `marks/<markId>/` before the DB row exists; `cost = cp.cost ?: 0` (0 while locked, real value after reveal); anti-cheat coordinate attached via the existing `attachLocation` path. `attachPhotos(markId, newPaths, now)` — column-scoped `@Transaction` that reads + merges + writes `photoPath`/`updatedAt`/`photosUploaded*` (**does not reset `uploaded*`** — `photoPath` is not in the marks DTO; **does reset `photosUploaded*`** to re-queue the frame drain). - `data/time/TrustedClock.kt` — pure trusted-time core. Derives **trusted** time from the monotonic `elapsedRealtime()` + server time (`trusted = serverEpochMs + (elapsedNow − anchorElapsedMs)`) — immune to wall-clock changes; only a **reboot** breaks it (detected by monotonic regression and/or `BOOT_COUNT` mismatch). `TimeSample` is one atomic snapshot of all time sources; `signingSeconds()` feeds request `ts`; `trustedAt(elapsedAt, bootAt)` extends the formula to an arbitrary past monotonic moment (the per-fix GPS anchor **and** the marks/judge-scan upload backfill — reboot-checked by boot id only, never by regression, since a pre-anchor point legitimately has `elapsedAt < anchorElapsedMs`). **Warm start through boot identity** (`null == null` does NOT grant warm start — would falsely verify a reboot). **Uncertainty-based re-anchor** — `onTimeCandidate(candidate: TimeCandidate, wallNow, bootNow)` (renamed from `onServerTime`): every source (HTTP `Date`, GPS fix, LAN time endpoint) produces a pure `TimeCandidate(serverMs, anchorElapsedMs, uncertaintyMs)`, and `ClockAnchor` carries `uncertaintyMs` (source quality). Accept is unconditional on no-anchor / **unverified current anchor** (a warm-start anchor whose boot continuity couldn't be confirmed — null `BOOT_COUNT` at persist or read — is `NoSync` and forces wall-clock signing, so its stored uncertainty must never reject the first real candidate; that candidate is the re-verification) / reboot (monotonic regression or `BOOT_COUNT` change); otherwise, within one boot session **and only against a verified current anchor**, accept iff the candidate's **effective** uncertainty at `elapsedNow` is strictly lower than the current anchor's (`effective = uncertaintyMs + abs(Δelapsed) * DRIFT_PPM / 1_000_000`, `DRIFT_PPM = 20` ≈ 1.7 s/day — so a stale ideal anchor eventually loses to a fresh average one), **or** they tie on effective uncertainty and the candidate is monotonically fresher (`anchorElapsedMs >=`). At millisecond scale the drift term truncates to 0, so two equal-quality anchors tie and the `>=` tie-break drops a **late out-of-order duplicate** (older `anchorElapsedMs`); a candidate with `anchorElapsedMs` in the past (a pre-anchor GPS fix) is allowed (the age formula is symmetric in the sign of Δ). Lock-free reads via `AtomicReference`; all writes under one lock; `persist` is best-effort (never throws on the OkHttp thread). Tested by `TrustedClockTest`.
- `data/time/GpsTimeCandidate.kt` — pure `gpsTimeCandidate(fix: RawFix): TimeCandidate?`, the **offline** trusted-time source (forest / local mode / post-reboot with no network). Rejects `isMock`, a non-satellite fix, `gpsTimeMs <= 0`, `accuracy > 100 m`; pins `Location.time` to the fix's monotonic moment (`elapsedRealtimeNanos / 1_000_000`) with `GPS_UNCERTAINTY_MS = 500` (deliberately on par with the `Date` candidate so a good GPS and a good network fix are peers). **Satellite-backed test** (`isSatelliteBacked`): `"gps"` is trusted by provider name (the legacy `GPS_PROVIDER` is an OS guarantee of a satellite source, so a 2-D gps fix with no altitude still passes). `"fused"` — the only provider a **GMS device** (the majority) ever reports and what both anchor power points use — is ambiguous: a fused fix may be a real GNSS lock **or** a WiFi/cell-blended fix whose `time` is just the (spoofable) device wall-clock (`isMock` stays `false` when the user merely changes the Settings clock, and a WiFi fix's ~20–60 m accuracy passes the coarse 100 m gate). A pure GNSS lock is 3-D and reports `altitude`; a pure WiFi/cell 2-D radio fix does not — so a `"fused"` fix is trusted **only** when `altitude != null`. This is a **heuristic that raises the spoofing bar, not a guarantee** that a fused fix is satellite-sourced, and it is imperfect in **both** directions: (a) *false positive* — `FusedLocationProviderClient` is a black box that can attach a barometer or cached-GNSS altitude onto a WiFi-horizontal fix, so `altitude != null` does **not** prove the `time` is GNSS-derived; the guard *narrows* the spoofed-clock overwrite vector (a forged-time WiFi fused fix would else beat a legitimate cloud `Date` anchor via the effective-uncertainty rule) but does not eliminate it — the real last line is server-side fraud checks; (b) *false negative* — a 2-D-only GNSS fix (3-sat lock under dense canopy, the target offline scenario) carries valid satellite time but no altitude, so on GMS it is conservatively rejected and the clock falls back to `NoSync` (safe). Kept conservative on purpose: for a security gate, rejecting an ambiguous legit fix (→ `NoSync`) is safer than accepting a spoofable one (→ forged anchor). `verticalAccuracyMeters` is a stronger signal but API 26+ only, so it is not required (would make the anchor inert on API 24/25). Two impure injection points feed candidates in, both via `AppContainer.anchorTrustedTimeFromGps` (which snapshots wall+boot): the `TrackRecordingService` fix path (every recorded fix) and the one-shot `CurrentLocationProvider` (wrapped by a decorator in `AppContainer` — КП-scan take coordinate + the judge screen's «Время по GPS» button); the replacement rule keeps only fixes that improve the anchor. Tested by `GpsTimeCandidateTest`.
- `data/time/LanTimeVerifier.kt` — pure verifier making the LAN server a legitimate trusted-time anchor **in local mode** (the cleartext `Date` header is MITM-forgeable, but an HMAC-signed body with a fresh client nonce is tamper/replay-evident — an attacker can't produce `HMAC(APP_SECRET, "<nonce>|<server_ms>")`, and a replayed old response carries a stale nonce). `newNonce()` (injectable RNG → 32-hex); `verify(sentNonce, dto, signature, elapsedBefore, elapsedAfter): TimeCandidate?` rejects a missing body/signature, RTT out of `0..maxRttMs`, a mismatched nonce echo, or a bad HMAC (constant-time `MessageDigest.isEqual`, reuses `AppSignatureInterceptor.sign`); on accept pins `server_ms` to the RTT-corrected midpoint with `uncertaintyMs = rtt/2 + LAN_TIME_GRANULARITY_MS` (50 — the ms-granular body beats the second-granular `Date` candidate). Never throws. Wired in `AppContainer.syncLanTime` (fresh nonce → `localApiClient.fetchLanTime` → verify → `onTimeCandidate`, RTT measured around the call since the LAN client carries no `ServerTimeInterceptor`), fired from `SyncCoordinator.probeLocalAndRenew`/`enterLocalMode` **before** the freshness-checked manifest fetch so a skewed clock is anchored in time to re-sign the manifest. Contract in `docs/design/UPLOAD.md`. Tested by `LanTimeVerifierTest`.
- `data/AdminAuthRepository.kt` + `data/AdminTokenStore.kt` — race-admin session. `AdminSession { LoggedOut | LoggedIn }` seeded **synchronously** from the store (a past-expiry stored session → `LoggedOut`+cleared); `token()` is a synchronous `.value` read (so the OkHttp thread can call it). `login`/`logout` (logout always clears locally even offline)/`onUnauthorized`. Pure `isExpired` is a **lexicographic** UTC-string compare. The 30-day bearer is revocable, so plain prefs is acceptable. Tested by `AdminAuthRepositoryTest`/`AdminTokenStoreTest`.
- `data/ThemePreference.kt` / `data/TrackProfilePreference.kt` / `data/time/ClockAnchorStore.kt` / `data/InstallId.kt` — pure injected `load`/`save` stores + thin `fromSharedPreferences` adapters, read **synchronously** at construction (no cold-start flash). `ClockAnchorStore` writes the anchor as **one delimited key** (atomic — a kill mid-write can't leave a half-written mix), now **5 segments** (`server|elapsed|wall|boot|uncertainty`); `read()` still accepts a **legacy 4-segment** string (→ `uncertaintyMs = LEGACY_UNCERTAINTY_MS = 5_000`, conservative so a fresh candidate supersedes it), and a non-numeric 5th segment → `null`. All pure parts unit-tested.
- `data/NfcUid.kt` — pure `normalizeNfcUid(raw: ByteArray): String` (per-byte zero-padded hex, uppercased, matching the server pool format). Tested by `NfcUidTest`.
- `data/DateUtils.kt` — `todayIso()` + `nearestRaceId(races, today)` (soonest current race), both `SimpleDateFormat`-based.
- `TrackRecordingService.kt` — foreground service (`type=location`, `START_NOT_STICKY` — a kill does not silently resume). Re-checks location permission first thing (TOCTOU on a revoke). Reads the active `TrackProfile`, mints one `segmentId` per recording session (pure `nextSegmentId`), batches `RawFix → trackRepository.insertAll` (also offering each fix to `container.anchorTrustedTimeFromGps` — the offline trusted-time anchor; the replacement rule keeps only the best), and **flushes the buffer before stop** (`flushThen` runs `after` exactly once via callback or a ~4 s timeout fallback — fixes a «Стоп»-drops-last-batch bug). **Live-apply** profile toggle via a `profileJob` soft engine restart (no track gap). **Throttled live upload** piggybacks `trackRepository.uploadPending` + `markRepository.uploadPending` every `LIVE_UPLOAD_MIN_INTERVAL_MS` (10 min) via pure `shouldLiveUpload` (nullable "never uploaded" sentinel so the first batch always fires). **Guarantee:** «Стоп» + live-switch are lossless; a bare `onDestroy()`/hard kill may lose up to `maxDelay` (best-effort). Pure helpers tested (`SegmentIdTest`/`LiveUploadThrottleTest`); the service is not.
